# MeshCore Санкт-Петербург — контекст проекта

## Что это

Одностраничный статический сайт в корне `https://meshcore.spb.ru/` о
MeshCore в Санкт-Петербурге. Заменяет текущий редирект с корня
на вики. `/wiki/` и `/flasher/` остаются отдельными приложениями и не
затрагиваются.

Главный читатель — человек, у которого нода MeshCore уже есть на руках.
Он должен быстро найти прошивальщик, настройки сети и вход в общий канал.
Второстепенный читатель — новичок, который впервые слышит про MeshCore;
для него есть короткое объяснение и дорога в вики.

Задача страницы: за 1,5–2 экрана провести по пути «понял → прошил →
настроил → поздоровался в Public».

## Технические ограничения

- Только статика. Никакой сборки, npm, фреймворков, отдельных JS-файлов.
- Единственный скрипт — встроенный счётчик Яндекс Метрики.
- Стили подключаются как `style.css?v=5`. При изменении CSS версию
  в `index.html` нужно увеличить.
- Шрифт только `Arial, Helvetica, sans-serif`, без веб-шрифтов.
- Никаких анимаций, кроме переходов цвета 0.15 s. При
  `prefers-reduced-motion: reduce` переходы отключаются.
- Страница не должна иметь горизонтальной прокрутки на 320 px.
- Сеть 433 МГц не упоминается: только 868.

## Стиль

Палитра взята из прошивальщика и вики:

- фон страницы `#f5f5f5`, поверхности `#ffffff`
- тёмно-синий `#001a4d`, синий `#0042aa`, голубой `#e3edff`
- оранжевый `#f26a21`, светло-оранжевый `#fff0e7`
- текст `#10233f`, приглушённый `#5d6f88`, обводка `#c3d0e3`
- радиус 3 px
- заголовки тёмно-синие, основной текст приглушённый
- главная кнопка: оранжевый фон, тёмно-синий текст
- вторичная кнопка: белый фон, синяя обводка и текст
- крупная типографика: H1 `clamp(2.2rem, 6vw, 4rem)`, H2

- контейнер `min(1040px, 100% - 40px)`

- брейкпоинты: 900 px (герой в одну колонку), 800 px (шаги в столбик),
  480 px (мелкие отступы, сетка настроек 2 колонки)

Композиция:

## Графика

Внизу первого экрана — inline SVG с силуэтом города и сетью. На
десктопе и планшетах — сцена `viewBox="0 0 1200 220"` на всю ширину,
с Лахта-центром, Петропавловским собором, Исаакиевским собором и
Ростральной колонной. На экранах ≤ 560 px показывается отдельная
упрощённая сцена `viewBox="0 0 390 150"` с тремя landmarks и четырьмя
узлами, иначе на телефоне силуэт становится слишком мелким. Обе сцены
декоративные, с `aria-hidden="true"`, без анимации.

Никаких стоковых фото, иконок шагов и фоновых волн.

## Выкладка

На сервер копируются только `index.html`, `style.css`, `logo.jpg` и
`favicon.png`.
В nginx нужно убрать правило, которое отдаёт 301 с `/` на `/wiki/start`,
иначе новый `index.html` не откроется. `/wiki/` и `/flasher/` не трогать.

## Проверка

Локальный сервер:

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

Скриншоты:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --hide-scrollbars \
  --screenshot=/tmp/mesh-1440.png --window-size=1440,900 \
  http://127.0.0.1:8080/
```

Проверить ширины 1440, 1024, 768, 390 и 320 px. На 1440×900 высота
документа должна быть примерно 1600–2000 px. Проверить отсутствие
горизонтальной прокрутки, читаемость значений настроек, видимый фокус с
клавиатуры и то, что метрика не грузится на localhost.

## Принятые решения

- План и дизайн-документ не хранятся в репозитории по просьбе владельца.
  Их место — `/Users/alexxx/.opencode/plan/`.
- Работа ведётся прямо в корне проекта, без отдельного worktree: репозиторий
  новый и пустой, веток и общего main ещё нет.
- Автотестов нет: проект статический, проверка — HTTP-код, скриншоты в
  headless Chrome и ручная проверка ссылок. Это осознанное отклонение от
  TDD-процесса, а не забытые тесты.
